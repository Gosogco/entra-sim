Connecting clients

How to point Terraform, the Azure SDKs, MSAL in a browser and your own APIs at the simulator, and the examples that do it.

Trusting the CA

Every client must trust the simulator's CA (certs/ca.pem) or a certificate you supplied. Each runtime reads its own setting:

RuntimeSetting
Go, including Terraform providersSSL_CERT_FILE=$PWD/certs/ca.pem
Node.jsNODE_EXTRA_CA_CERTS=$PWD/certs/ca.pem. Node does not read the operating system store.
Python requestsREQUESTS_CA_BUNDLE=$PWD/certs/ca.pem
curl--cacert certs/ca.pem
BrowsersA certificate from a CA in the browser's store, such as one made with mkcert, passed as ENTRA_SIM_TLS_CERT and ENTRA_SIM_TLS_KEY

Terraform (hashicorp/azuread)

export ARM_METADATA_HOSTNAME=localhost:8443
export SSL_CERT_FILE=$PWD/certs/ca.pem
export ARM_TENANT_ID=00000000-0000-0000-0000-000000000001
export ARM_CLIENT_ID=11111111-1111-1111-1111-111111111111
export ARM_CLIENT_SECRET=entra-sim-bootstrap-secret

terraform init
terraform apply
terraform plan -detailed-exitcode    # 0: no drift

The .tf files need no change; unset ARM_METADATA_HOSTNAME to use a real tenant again.

metadata_host (ARM_METADATA_HOSTNAME) is the provider's only hook for this. The provider fetches https://{metadata_host}/metadata/endpoints?api-version=2022-09-01 and reconfigures every endpoint from it:

FieldUse
nameMust not be empty
resourceManagerMust not be empty; azuread never calls it
microsoftGraphResourceIdBoth the Graph base URL and the token resource: the provider asks for {microsoftGraphResourceId}/.default
authentication.loginEndpointThe base of the token URL, joined as {loginEndpoint}/{tenant}/oauth2/v2.0/token, so the simulator sends it without a trailing slash

The provider forces HTTPS for this request, which is why the simulator serves TLS itself. It uses /beta for several resources, which the simulator serves with the same handlers as /v1.0.

Resources and data sources exercised in CI by tests/terraform/ (apply, empty plan, destroy): azuread_domains, azuread_service_principal (data), azuread_user, azuread_group, azuread_group_member, azuread_application, azuread_service_principal, azuread_application_password, azuread_application_certificate, azuread_app_role_assignment, azuread_conditional_access_policy, azuread_directory_role_eligibility_schedule_request, azuread_directory_role, azuread_administrative_unit, azuread_administrative_unit_member and azuread_administrative_unit_role_member.

Azure SDKs and application code

export AZURE_AUTHORITY_HOST=https://localhost:8443/
export AZURE_TENANT_ID=00000000-0000-0000-0000-000000000001
export AZURE_CLIENT_ID=11111111-1111-1111-1111-111111111111
export AZURE_CLIENT_SECRET=entra-sim-bootstrap-secret

Request Graph tokens as in a real tenant, with https://graph.microsoft.com/.default or a bare scope such as User.Read, and send Graph requests to https://localhost:8443/v1.0/… instead of https://graph.microsoft.com/v1.0/…. Request tokens for your own API with its identifier URI or appId.

A client that reads OIDC discovery takes https://localhost:8443/{tenant}/v2.0/.well-known/openid-configuration.

Your own API validating tokens

  • An API that accepts v2.0 tokens (requestedAccessTokenVersion: 2) reads https://{public-host}/{tenant}/v2.0/.well-known/openid-configuration and expects aud to be its appId.
  • An API that accepts v1.0 tokens (the default) reads https://{public-host}/{tenant}/.well-known/openid-configuration, whose issuer is https://sts.windows.net/{tenant}/, and expects aud to be the identifier URI or appId the client asked with.
  • Both documents point at the same key.

Tokens lists the claims.

MSAL in a browser

msal-browser works in its normal AAD protocol mode. The simulator sends cross-origin headers, supports the fragment response mode MSAL uses, and serves GET /me. MSAL asks Microsoft's instance discovery whether an authority is genuine, which for a local simulator is wrong and unreachable, so the answer is supplied inline:

auth: {
  clientId: '…',
  authority: 'https://localhost:8443/{tenant}',
  knownAuthorities: ['localhost:8443'],
  cloudDiscoveryMetadata: JSON.stringify({
    tenant_discovery_endpoint:
      'https://localhost:8443/{tenant}/v2.0/.well-known/openid-configuration',
    'api-version': '1.1',
    metadata: [{
      preferred_network: 'localhost:8443',
      preferred_cache: 'localhost:8443',
      aliases: ['localhost:8443'],
    }],
  }),
}

Against a real tenant both settings are left unset. Register the app's redirect URI under spa.redirectUris, as in Entra.

Examples

DirectoryWhat it shows
examples/react-spa/A React single-page app that signs in with MSAL and calls GET /me. The same build runs against the simulator and a real tenant; only .env differs. Terraform or scripts/setup.sh creates its app registration and user. A Playwright suite signs in, checks that no request reaches a Microsoft host, calls Graph, and checks that revoking consent narrows the next token. ./run.sh does everything.
examples/terraform-users-app-roles/Five users and two APIs, Orders and Inventory, each with the app roles Reader, Writer and Admin, assigned to users. ./token.sh bob orders signs a user in through a public client and prints the access token, showing roles in a v1.0 token.
tests/terraform/The Terraform acceptance fixture listed above.

Each example's README has the details. The examples start a simulator container named entra-sim-examples when none is running on ports 8080 and 8443, and reuse one that is.
