Running

The container image, its ports and certificates, the bootstrap client, and recipes for Docker Compose and GitHub Actions.

From a checkout

./run.sh

run.sh builds the image as entra-sim:local, replaces any container named entra-sim, starts it with ports on 127.0.0.1 and the log on the Docker volume entra-sim-logs, waits for the health check, and opens the studio at http://localhost:8080/. Stop it with docker stop entra-sim. The log survives a stop; docker volume rm entra-sim-logs empties it.

The published image

mkdir -p certs
docker run --rm --name entra-sim --user "$(id -u):$(id -g)" \
  -p 127.0.0.1:8080:8080 -p 127.0.0.1:8443:8443 \
  -v "$PWD/certs:/certs" \
  ghcr.io/gosogco/entra-sim:latest

Each release is published as latest, {major}, {major}.{minor} and the exact version, for example ghcr.io/gosogco/entra-sim:1.0.0.

PortProtocolUse
8443HTTPSTerraform and any client that needs TLS. The URLs the simulator advertises point here.
8080HTTPHealth checks, the control endpoints, simple clients. Both ports serve the studio at /.

The image sets ENTRA_SIM_BIND=0.0.0.0, ENTRA_SIM_TLS_SAN=localhost,127.0.0.1,entra-sim, ENTRA_SIM_CA_OUT=/certs/ca.pem, ENTRA_SIM_PUBLIC_HOST=localhost:8443, ENTRA_SIM_STUDIO_DIR=/usr/share/entra-sim/studio and ENTRA_SIM_LOG_DIR=/logs, and has a health check. The 127.0.0.1: prefix on -p keeps the ports off the network.

Waiting until it is ready

The container generates an RSA signing key at startup, which takes a few seconds:

until curl -sf -o /dev/null http://127.0.0.1:8080/__sim__/health; do sleep 1; done

The health endpoint answers {"status":"ok","version":"…","tenant_id":"…"}.

Certificates

The simulator terminates TLS itself, because the Terraform provider forces HTTPS when it fetches the metadata document. At startup it generates a CA and a server certificate for the names in ENTRA_SIM_TLS_SAN, and writes the CA to ENTRA_SIM_CA_OUT. Clients are told to trust that file.

-v "$PWD/certs:/certs" is a bind mount: the host directory and /certs are the same directory. Two rules follow:

  1. Create the directory first. Docker creates a missing one owned by root, and the container's own user then fails with Error: writing CA certificate to /certs/ca.pem … Permission denied (os error 13).
  2. The container must be able to replace the file. The image runs as user 10001, which cannot replace a ca.pem owned by you or by root.

--user "$(id -u):$(id -g)" satisfies both: the container writes as you. Without it, use mkdir -p certs && chmod 777 certs and remove any old ca.pem.

The CA changes on every restart. A client holding the previous ca.pem fails with "certificate signed by unknown authority". Read the file again after a restart, or supply a fixed certificate with ENTRA_SIM_TLS_CERT and ENTRA_SIM_TLS_KEY. A browser needs a certificate it trusts; the React example uses mkcert for that.

The signing key also changes on every restart, so kid changes. Set ENTRA_SIM_SIGNING_KEY to a PKCS#8 PEM RSA key to keep it, for example one made with openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048.

The bootstrap client

The directory starts with the Microsoft Graph service principal and one application, so a client can authenticate from a cold start. There are no users.

Tenant ID00000000-0000-0000-0000-000000000001ENTRA_SIM_TENANT_ID
Tenant domainentra-sim.testENTRA_SIM_TENANT_DOMAIN
Client ID11111111-1111-1111-1111-111111111111ENTRA_SIM_BOOTSTRAP_CLIENT_ID

Its object IDs are derived from the client ID, so they are the same after a restart.

A first token and Graph call

TOKEN=$(curl -s --cacert certs/ca.pem \
  -d grant_type=client_credentials \
  -d client_id=11111111-1111-1111-1111-111111111111 \
  -d client_secret=entra-sim-bootstrap-secret \
  -d 'scope=https://graph.microsoft.com/.default' \
  https://localhost:8443/00000000-0000-0000-0000-000000000001/oauth2/v2.0/token \
  | jq -r .access_token)

curl -s --cacert certs/ca.pem -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"accountEnabled":true,"displayName":"Alice","mailNickname":"alice",
       "userPrincipalName":"alice@entra-sim.test",
       "passwordProfile":{"password":"P@ssw0rd!"}}' \
  https://localhost:8443/v1.0/users

curl -s --cacert certs/ca.pem -H "Authorization: Bearer $TOKEN" \
  'https://localhost:8443/v1.0/users?$select=id,userPrincipalName' | jq

The public host

ENTRA_SIM_PUBLIC_HOST is the host and port in every URL the simulator emits: the metadata document, discovery, iss, and the aud of Graph tokens. Clients must reach the simulator at exactly that address, and the server certificate must cover its host name (ENTRA_SIM_TLS_SAN). A mismatch gives tokens that Graph refuses with "Invalid audience".

Docker Compose

services:
  entra-sim:
    image: ghcr.io/gosogco/entra-sim:latest
    ports: ["127.0.0.1:8080:8080", "127.0.0.1:8443:8443"]
    volumes: ["./certs:/certs"]
    environment:
      ENTRA_SIM_TLS_SAN: localhost,127.0.0.1,entra-sim
      ENTRA_SIM_PUBLIC_HOST: entra-sim:8443

  my-app:
    build: .
    depends_on:
      entra-sim:
        condition: service_healthy
    volumes: ["./certs:/certs:ro"]
    environment:
      SSL_CERT_FILE: /certs/ca.pem
      AZURE_AUTHORITY_HOST: https://entra-sim:8443/

Other containers reach the simulator by its service name, so that name goes in ENTRA_SIM_TLS_SAN and ENTRA_SIM_PUBLIC_HOST. The image's own health check makes service_healthy work.

GitHub Actions

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      entra-sim:
        image: ghcr.io/gosogco/entra-sim:latest
        ports: ['8080:8080', '8443:8443']
    steps:
      - uses: actions/checkout@v5

      # A service container cannot share a volume with the job, so copy the CA out.
      - name: Get the CA certificate
        run: |
          until curl -sf -o /dev/null http://localhost:8080/__sim__/health; do sleep 1; done
          docker cp "$(docker ps -qf ancestor=ghcr.io/gosogco/entra-sim:latest)":/certs/ca.pem ca.pem

      - name: Test
        env:
          SSL_CERT_FILE: ${{ github.workspace }}/ca.pem
          ARM_METADATA_HOSTNAME: localhost:8443
          ARM_TENANT_ID: 00000000-0000-0000-0000-000000000001
          ARM_CLIENT_ID: 11111111-1111-1111-1111-111111111111
          ARM_CLIENT_SECRET: entra-sim-bootstrap-secret
        run: ./run-tests.sh

Running the binary

cargo run --release -- --ca-out certs/ca.pem

Outside a container the simulator binds to 127.0.0.1 by default and serves nothing at / unless given --studio-dir pointing at a build of studio/.
