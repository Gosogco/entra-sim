Limits

What the simulator does not implement, and where it knowingly behaves differently from Entra.

Out of scope

  • Entitlement management, synchronization jobs, devices, licences, mail, calendars, files, photos and every other Graph area not listed in the endpoint reference.
  • Eventual consistency: a write is readable at once.
  • Deleted items: a delete is permanent and cannot be restored.
  • Personal Microsoft accounts. consumers is accepted as a tenant alias only.

Identity platform

AreaDifference from Entra
FlowsOnly response_type=code. The implicit and hybrid flows, SAML, WS-Federation and the v1.0 protocol endpoints (/oauth2/authorize, /oauth2/token) are not implemented. The v1.0 discovery document holds only the issuer and the keys.
Confidential clientsThe authorization code, refresh and device code grants check a client credential only when one is presented, and PKCE only when the authorize request used it. Entra requires a confidential client to authenticate.
Graph token audienceaud is the simulator's URL, not https://graph.microsoft.com.
Graph token claimsGraph tokens carry no amr, group claims, wids or optional claims.
On-behalf-of and MFAMFA carries over only when the incoming token's amr says so. A v2.0 token has amr only when its API requests the optional claim.
email claimThe rule follows Microsoft's documentation and has not been compared with a real tenant.
Pre-authorized applicationsapi.preAuthorizedApplications is read only from an API registered in the same tenant.
AADSTS501051Returned for an unassigned client, as Entra does, but the code is not in Microsoft's error reference.
MultitenantA single-tenant application used through common or organizations is refused with AADSTS50194. The control endpoints act on the primary tenant, and a seed describes it only.
UserInfopicture points at /v1.0/me/photo/$value, which the simulator does not serve.

Conditional access

  • Locations, platforms, devices, sign-in, user and service principal risk, insider risk and authentication flows are unknown to the simulator. A policy restricted by one of them never applies.
  • Policies for workload identities are not enforced.
  • An authenticationStrength is treated as MFA.
  • Device, terms-of-use and custom controls cannot be satisfied and always refuse.
  • sessionControls are stored and not enforced.

Microsoft Graph

AreaDifference from Entra
Query options$search is refused. $expand covers members and owners on groups only.
Delta queriesNo paging: every round is one page. The last 1000 delta tokens are remembered.
Directory role checks on user tokensOnly PATCH and DELETE on another user check the signed-in user's directory roles, and only Global Administrator and User Administrator count. Every other delegated call is judged on scp alone.
Role assignmentsPOST /roleManagement/directory/roleAssignments ignores directoryScopeId, so an assignment meant for an administrative unit becomes tenant-wide. Use a scoped role membership or a PIM request for a unit.
PIMRequests never wait for approval, cancel is always refused, and PIM for groups and Azure resources is not present.
Administrative unitsDynamic membership rules are not evaluated, and restricted management units do not shut out tenant administrators.
Permission table gapsGET /servicePrincipals/{id}/appRoleAssignedTo/{assignment-id}, GET /servicePrincipals/{id}/appRoleAssignments/{assignment-id} and GET /users/{id}/appRoleAssignments/{assignment-id} have no generated requirement, so they are allowed with a warning in the log.

Security

The simulator is a test tool. Its control endpoints are unauthenticated, the snapshot and the request log contain every secret and token, and the bootstrap secret is public. Keep it on 127.0.0.1 or a private network, and never load real credentials into it.
