Testing and the studio

State is held in memory. The endpoints under /__sim__ inspect and manage it, and the studio shows it in a browser.

Control endpoints

The /__sim__ prefix cannot collide with a Graph or identity path. The endpoints need no token: anyone who can reach the simulator can already mint a token for any identity in it.

RequestResult
GET /__sim__/healthstatus, version and the primary tenant_id
POST /__sim__/resetRebuilds every tenant's directory from the bootstrap objects and the seed, and drops all codes, refresh tokens, sessions, device codes and the token list. Returns the object counts.
GET /__sim__/snapshotThe primary tenant's whole directory, secrets included
POST /__sim__/snapshotReplaces the primary tenant's directory with the body. The bootstrap objects are reinstalled over it, so the bootstrap client always works.
GET /__sim__/tokensThe last 1000 tokens issued, newest first, with client, subject, audience, scopes, roles and expiry; and the refresh tokens and codes still redeemable. No token values; refresh tokens and codes show their first six characters.
GET /__sim__/logsThe request and event log, newest first, 200 entries at a time

Reset between test cases:

curl -X POST http://127.0.0.1:8080/__sim__/reset

Seed files

A seed is a snapshot loaded at startup and on every reset, so a suite resets between cases and lands back on its fixtures.

# Build the state you want through Graph, then save it.
curl -s http://127.0.0.1:8080/__sim__/snapshot > seed.json

docker run … -v "$PWD/seed.json:/seed/tenant.json:ro" -e ENTRA_SIM_SEED=/seed/tenant.json …

The file is read again on each reset, so an edit takes effect without a restart. A seed that cannot be read or parsed stops startup rather than leaving an empty tenant. A seed describes the primary tenant only.

The request log

With --log-dir (ENTRA_SIM_LOG_DIR; the image sets /logs), the simulator appends to entra-sim.jsonl, one JSON object per line:

  • every request with its headers and both bodies, unmodified, so secrets and tokens are in the file;
  • every event the simulator logs at debug level or above, tied to the request it happened in.

Nothing trims the file and a reset leaves it alone. The studio's own reads of /__sim__/* and of its files are not logged.

GET /__sim__/logs pages through it: limit sets the count (default 200), before=N returns entries older than entry N, and after=N returns the oldest entries newer than N, so a poller misses nothing. Without a log directory it answers "enabled": false.

With run.sh, the log lives on the volume entra-sim-logs:

docker run --rm -v entra-sim-logs:/logs debian:trixie-slim cat /logs/entra-sim.jsonl

The studio

A read-only browser view at / on both ports, built from studio/ and served from --studio-dir. Its tabs:

TabShows
OverviewThe version, tenant ID and clock offset, object counts, active tokens, and credentials and tokens about to expire
Users, GroupsUsers, groups and their memberships
App registrations, Enterprise appsApplications and service principals
PermissionsApp role assignments and delegated permission grants
Directory rolesActivated roles and their members
TokensGET /__sim__/tokens
LogGET /__sim__/logs, with each request's details

The tab is kept in the URL hash, so a reload or a shared link opens the same view.

Tests without a browser

  • ENTRA_SIM_AUTO_SIGN_IN_USER=alice@entra-sim.test makes the authorize endpoint redirect at once with a code for that user.
  • The password grant signs a user in with one request, for a client with isFallbackPublicClient or a secret.
  • The device code flow can be completed by posting to /devicelogin with user_code and user_id.
  • ENTRA_SIM_ENFORCE_PERMISSIONS=false lets tests run before permissions are granted.
